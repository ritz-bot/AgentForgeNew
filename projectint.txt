### Project Overview: Building a Multi-AI Agent System

This project focuses on creating a customizable multi-AI agent application. Users can select the type of agent (e.g., financial, medical, study-related, or any other) and ask specific questions. For example:
- A medical agent can answer queries about diseases.
- A financial agent can provide info on stocks.
- The agent uses AI to process and respond intelligently.

The demo video (already shown) illustrates how it works: User inputs agent type and question, and the system generates a response. The core idea is to combine an LLM (Large Language Model) with internet search for up-to-date answers, avoiding outdated LLM training data (e.g., cut off at 2021).

### Key Tech Stacks and Their Roles

The project uses a combination of tools for AI, backend, frontend, code quality, CI/CD, and deployment. Here's a breakdown:

1. **Grok (as LLM via Grok Cloud)**:
   - Free to use.
   - Acts as the core language model to generate responses.
   - Offers various models (e.g., Llama, Gemma); in this project, we'll use Llama 3.
   - Limitation: Trained on data up to a certain cutoff (e.g., 2021), so it can't provide latest info (e.g., 2025 stock trends) without external help.

2. **Tavily (Online Search Tool)**:
   - Free API for fetching real-time internet data.
   - Integrated to overcome LLM limitations—e.g., for latest news, stocks, or events.
   - Workflow: User asks a question (e.g., "Top stocks in 2025?") → Tavily searches online → LLM (Grok) analyzes results → Generates accurate, current response.
   - Example: Without Tavily, LLM might suggest 2021 stocks; with it, you get 2025 data.

3. **LangChain (Generative AI Framework)**:
   - Used to interact with the LLM (Grok).
   - Handles prompt engineering, chaining responses, and integrating tools like Tavily.

4. **LangGraph (Agentic AI Framework)**:
   - Built on top of LangChain.
   - Specifically for creating AI agents and their workflows (e.g., decision-making, multi-step processes).
   - Enables "agentic" behavior: Agents can reason, use tools (like search), and execute tasks.

5. **FastAPI (Backend)**:
   - Creates the backend server to handle user requests (e.g., process agent type, question, and forward to AI logic).
   - Receives input from frontend, processes via AI, and returns output.

6. **Streamlit (Frontend/UI)**:
   - Builds a simple web-based UI.
   - User form: Select agent type, enter question, click "Generate".
   - Displays the AI-generated response.
   - Connects to backend for input/output flow.

7. **Docker (Containerization)**:
   - Key for production-grade projects.
   - Packages the entire app (code, dependencies) into containers for easy deployment on any platform (e.g., AWS, GCP).
   - Used in every project in this course.

8. **SonarQube (Code Quality Tool)**:
   - Open-source and free; MVP (Most Valuable Player) of the project along with Jenkins.
   - Scans code for issues to ensure high quality.
   - Focuses on three main areas:
     - **Bugs**: Errors that cause weird behavior. Example: "Dead code bug" – Code that never executes, like a redundant `elif` block in an if-else chain (e.g., two identical conditions for "Hi" – the second one is unreachable).
     - **Code Smells (Bad Practices)**: Not errors, but poor habits affecting readability/maintainability. Examples:
       - A single function with 300-800 lines → Split into smaller functions (e.g., 100 lines each) for better readability and analysis.
       - Using double quotes for very long strings → Use triple quotes or multi-line comments for clarity.
       - Goal: Make code easier to read, debug, and maintain.
     - **Code Duplication**: Repeating the same code in multiple files (e.g., identical functions in app.py, main.py, test.py) → Refactor by creating one function and importing it elsewhere.
   - Also checks security, but focus here is code quality.
   - Integrated into CI/CD to scan before deployment.

9. **Jenkins (CI/CD Pipeline Tool)**:
   - Another MVP; automates the build, test, deploy process.
   - Workflow:
     - GitHub acts as SCM (Source Code Management) to store and track code versions.
     - Jenkins fetches code from GitHub.
     - Builds Docker image using Dockerfile.
     - Pushes image to AWS ECR (Elastic Container Registry – AWS's Docker Hub equivalent).
     - Deploys to AWS ECS Fargate (serverless container service for running apps).
   - Entire process runs with one click (e.g., button in Jenkins).
   - Stages (detailed below in pipeline section).
   - GitHub integration for code versioning.

10. **AWS Services (Deployment)**:
    - **ECR**: Stores Docker images.
    - **ECS Fargate**: Runs the containerized app (serverless, no need to manage servers).
    - Challenge: Integrate a Load Balancer (e.g., ALB – Application Load Balancer) for a static URL. Without it, Fargate gives dynamic URLs that change per deployment. With it, URL stays the same regardless of updates.

#### Introduction to Code Versioning
- Code versioning involves uploading your code to an SCM like GitHub.
- Benefits: Track all code changes, maintain versions of the code.

#### Creating the .gitignore File
- In the root directory of your project, create a file named `.gitignore`.
- In this file, list all files and folders you do not want to push to GitHub.
- Specific exclusions:
  - `venv/`: Do not push the virtual environment because its files are very large (around 1 GB to 1.5 GB). GitHub accommodates only 50 to 200 MB of data.
  - Project management details: Copy the relative path of these files/folders and paste them into `.gitignore`. Do not push these.
  - Logs (optional): If you want to push logs, you can; otherwise, exclude them.
  - `.env` file: Most important to exclude, as it contains personal information like API keys or tables.
- These four items (venv, project management details, optional logs, .env) are the main things not to push to GitHub.
- Save the `.gitignore` file after adding these.

#### Setting Up GitHub Repository
- Create a GitHub account if you don't have one.
- Create a new repository. Example name: "multi AI agent project".
- Do not add a README file during creation. Reason: Adding it prevents the display of important initial setup commands.

#### Line-by-Line Explanation of Dockerfile Code
The instructor explains the copied code line by line:

1. **FROM python:3.11-slim**:
   - This is the parent image for the Docker container.
   - Uses Python 3.11 slim image, meaning the container will run Python 3.11.
   - Reason for choosing 3.11: Versions like 3.13 or 3.9 are unstable; 3.11 is a stable version.

2. **ENV PYTHON_DONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1**:
   - These are essential environment variables that are generally included.
   - `PYTHONUNBUFFERED=1` helps with real-time logging (aids in logging output immediately).

3. **WORKDIR /app**:
   - Sets the working directory inside the Docker container to `/app`.
   - All subsequent commands will run relative to this directory inside the container.

4. **RUN Commands for System Dependencies**:
   - These lines install system dependencies.
   - They update the system libraries (e.g., `apt-get update` or similar).
   - Install build essentials, including tools like curl.
   - Remove additional/unneeded packages to save space.
   - These lines are optional but must be included for a production-grade project (can be avoided for fun/personal projects).

5. **COPY . .**:
   - Copies all contents from the local directory (everything visible on the left side in the IDE) to the `/app` directory inside the container.

6. **RUN pip install --no-cache-dir -e .**:
   - Installs project libraries, dependencies, and everything else.
   - This runs the `setup.py` file to install packages (similar to the `pip install` command used in the project setup video at the start).
   - The `--no-cache-dir` flag ensures no previous cache is recorded, allowing fresh restarts if the command needs to be run multiple times (prevents caching issues).

7. **EXPOSE 8501 9999**:
   - Exposes the ports used by the app.
   - Port 9999 is for the backend (as shown in `main.py`).
   - Port 8501 is the default for the frontend (Streamlit runs on 8501 by default).
   - Ports must be exposed for the app to work properly.

8. **CMD ["python", "app/main.py"]**:
   - This is the command to run the app inside the Docker container.
   - Equivalent to running `python app/main.py` in a local terminal (as demonstrated in the app code video).
   - The writing pattern is slightly different (array format for CMD), but it does the same thing.
   - The app will only run if the ports are exposed first; otherwise, it won't work.

### Detailed Summary of Cleanup Process Video Transcript

#### Deleting the ECS Cluster
- First, go to your ECS clusters in AWS.
- Open the cluster and click "Delete cluster".
- Confirm by copying the cluster name, pasting it in the confirmation field, and deleting.
- Reason: Prevents heavy charges if the cluster keeps running.
- It automatically deletes associated services and other things.

#### Deleting the ECR Repository
- Go to your ECR repo in AWS.
- Select it and delete the ECR repo.
- Optional, but recommended to clean up.

#### Optional: Deleting IAM User
- You can delete the IAM user if desired.
- It will not charge you, so it's up to you whether to keep or delete it.

#### Clearing Docker Resources
- Delete all Docker images, volumes, and builds to avoid errors in other projects (e.g., if project names or Docker image names are the same).
- Run the command in Ubuntu (WSL): `docker system prune -a --f`.
- Open Ubuntu terminal (search for "ubuntu" and open it).
- This deletes cache objects, images, etc., and reclaims space (e.g., 1.765 GB reclaimed in the example).
